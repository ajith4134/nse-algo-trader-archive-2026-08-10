## Intent
One surface showing EVERYTHING this project ever built / partially built / planned / discussed / had as
an idea / forgot-and-skipped / blocked — nothing omitted — modelled on the user's crypto Feature-Catalogue
+ Status-Wall (`likelihood-diagnostic-ohio-candles…/feature-catalogue.html`), which is *"generated · never
hand-edited · measured."* The point of the identify-first pass: no feature is invisible or silently
skipped again (anti-fixation, Rule M/K/N).

## Rule-R architecture (plan authored, status MEASURED)
1. **Authored plan** (`feature_catalogue_authored.json`) — intent only: section, feature, phase,
   forgotten-flag, note, sources, atlas-flag, and the inventory's *claimed* status (baseline, not trusted).
2. **Status prober** (`feature_catalogue_status_prober.py`) — the Rule-R generator: scans the LIVE
   `src/nse_algo_trader` module set (302 real .py on disk), resolves each row's cited module, and emits a
   **measured** status (`built`=code present & claimed built · `partial` · `unverified`=claims built but no
   module resolves · `blocked` · `planned`/`researched`/`discussed`/`idea`=no code, `not-built`). Stamps
   `generated_at`. Never defaults to done; unmeasurable → `unverified`/`not-built`, surfaced not hidden.
3. **Renderer** (`render_feature_catalogue_html.py`) — two surfaces, crypto design:
   - **Catalogue view**: stat-tiles (Features · Forgotten · P0–P3 · Blocked · Built% measured) · filter
     toolbar (search + phase pills + status pills + Forgotten-only + N/N shown + theme) · numbered sections
     w/ item counts · 3-col rows (feature │ phase pill │ note) · amber rail + `MISSED` tag on forgotten ·
     "most-forgotten" ranked · Phase-0 gate.
   - **Status Wall view**: card grid, each card = phase + **measured** badge (BUILT/PARTIAL/BLOCKED/
     UNVERIFIED/NOT-BUILT) + real source file + measured line; footer *"Generated by
     feature_catalogue_status_prober · never hand-edited · Measured <ts>."*
   - **Atlas view**: 16 trunks × branches, measured coverage (X/197 built).
4. **Wiring** (Rule G/N): served at `/catalogue` from `dashboard_server`; registered in the feature-surface
   registry + coverage manifest; linked from the main dashboard + `/map`.

## Acceptance (Rule R/N/O)
- [ ] Every build-status cell is machine-derived from the disk/AST, never the authored label; reconciled
      count shown (built-with-code vs unverified).
- [ ] All 905 items present, filterable; forgotten rows amber-railed; declined/blocked distinct.
- [ ] `generated_at` timestamp on the page; regenerates on load.
- [ ] Registered surface + coverage manifest; visible + screenshot-verified on the live dashboard.
- [ ] Palette: status colors always label+color (never color-alone); theme-aware light/dark; no dual-axis.

## dataviz decisions
Status = a **status palette** (good=built / warning=partial / serious=blocked / neutral=not-built / info=
planned), each rendered as a text badge (label+color, CVD-safe by construction). Phase = sequential blue
ramp P0→P3 (crypto `#0E4E63→#22738D`). Forgotten = amber accent `#A2650F` rail. Stat-tiles = hero numbers.
No charts requiring an axis; tables + tiles + cards only.

## Sourcing (Rule I / O.1)
No new OSS required — determined, not assumed. The surface is a self-contained HTML/CSS/JS page rendered
by the existing dashboard stack (FastAPI `dashboard_server` + the repo's `render_*_html.py` string-render
pattern already used for `render_dashboard_html`/`render_system_map_html`). Measurement uses Python stdlib
only (`os`/`ast` over `src/nse_algo_trader`), same ground-truth source as the SYSTEM_MAP extractor (Rule H).
Crypto reference renders `/map` with client-side `marked`+`mermaid`; this catalogue needs neither (static
tables/tiles/cards), so no CDN/vendor dep is added. Reused in-repo parts: `dashboard_feature_surface`
(registry), coverage manifest, `dashboard_server` routing. No candidate rejected because none was needed.
